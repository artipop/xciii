# Доксайт: руководство как сайт

`docs/guide/` — это и папка с markdown, и сам сайт. Корень VitePress лежит в
ней самой: конфиг в `docs/guide/.vitepress/`, страницы рядом, и ничего из
остального `docs/` — записок для тех, кто пишет код, — в публикацию попасть не
может. Конвенция «фича не закончена, пока `docs/guide/` не рассказал как»
остаётся ровно той же; изменилось только то, что теперь у этого есть адрес.

## Почему VitePress

Три причины, в порядке важности:

- **подсветка кода на сборке.** Shiki раскрашивает `json`, `bash` и всё
  остальное в момент сборки, в двух темах сразу — читателю не приезжает ни
  байта JavaScript ради цвета;
- **это Vite**, которым в этом репозитории уже собираются `webapp/` и `site/`:
  никакого третьего инструмента в голове;
- **тема настраивается переменными.** `custom.css` — это перевод токенов из
  `webapp/src/styles/_tokens.scss` в словарь VitePress, а не второй дизайн.

Сборка всех страниц занимает полторы секунды, на выходе — 1,3 МБ вместе со
шрифтами.

## Команды

```
cd docs/guide
npm ci
npm run dev      # http://localhost:5174/docs/, с горячей перезагрузкой
npm run build    # собирает в site/dist/docs
npm run preview  # посмотреть собранное
```

Порт прибит гвоздями (`--port 5174 --strictPort`), и это не педантизм: дев-сервер
лендинга занимает 5173, а VitePress, найдя порт занятым, молча уходит на
следующий — и по 5173 открывается сайт, у которого никакого `/docs/` нет.
Пусть лучше не поднимется с понятной ошибкой.

Дев-сервер сайта проксирует `/docs` на 5174 (`server.proxy` в
`site/vite.config.js`, с `ws` — иначе горячая перезагрузка руководства вечно
«connecting»). Так ссылка «Руководство» в шапке лендинга работает и на машине,
где обе половины подняты; в одиночку руководство открывается по своему адресу.

Собирают его обычно не отсюда, а из `site/`: **`npm run build:all`** — сайт, а
следом руководство. Порядок важен: сборка сайта чистит `dist/` перед собой, а
руководство пишет в `dist/docs`, чтобы деплой оставался одной папкой. `base` —
`/docs/`.

Адреса страниц — с `.html` (`cleanUrls: false`). Без расширения красивее, но
тогда убирать его должен хостинг, а GitHub Pages и голое ведро S3 этого не
делают: руководство, которое отвечает 404 в зависимости от того, куда его
выложили, хуже некрасивого адреса.

## Два языка

Русский — оригинал и корень сайта, английский — перевод под `/docs/en/`,
страница в страницу: `en/` повторяет дерево целиком, поэтому переключатель
языка в шапке всегда ведёт на ту же самую страницу, а не на главную.

Подписи экрана в английских страницах — **не перевод на глаз, а строки из
`webapp/i18n/en.json`**: там уже сказано, как кнопка называется по-английски, и
руководство, назвавшее её иначе, отправит читателя искать несуществующее.
Собрать глоссарий для новой страницы проще всего так — вытащить из русской
версии все `«…»` и найти их в `ru.json`, а рядом напечатать `en.json`.

Имена, которые приложение **даёт само** (вид и колонка «Входящие»), не
переводятся нигде: на английском экране они тоже написаны по-русски, и
английская страница честно так их и называет.

## Как добавить страницу

1. Положить `.md` в нужный раздел (`automation/`, `inbox/`, `settings/` — или
   рядом с `board.md`, если раздел из одной страницы). Заголовок страницы —
   её первый `#`.
2. Положить перевод в тот же путь под `en/`.
3. **Дописать строку в `sidebar` обеих локалей в `.vitepress/config.mjs`.** Без
   неё страница собирается и открывается по адресу, но в навигации её нет — а
   значит, для читателя её нет.

Ссылки между страницами — относительные, с расширением `.md`
(`../inbox/index.md`): VitePress превращает их в адреса сам, а на битой сборка
падает — это и есть проверка ссылок. Ссылки на `docs/*.md`, записки для
разработчиков, — абсолютные, на GitHub: они не часть этого сайта.

## Дизайн

- `.vitepress/theme/index.js` берёт `vitepress/theme-without-fonts`: та же
  тема, но без своих Inter и Punctuation — мегабайт woff2, которого никто бы не
  увидел;
- `custom.css` держит палитру (тёмная — экран, светлая — бумага), два шрифта и
  разрядку заголовков разделов: машина говорит капслоком, человек — прозой;
- `.vitepress/theme/fonts/` — копии тех же подмножеств, что лежат в
  `site/fonts/`. Лежат рядом с `custom.css`, а не в `public/`, чтобы Vite
  разрешал их на сборке и подставлял хеш в имя; дублирование с `site/`
  сознательное — доксайт так собирается и открывается сам по себе, не зная
  ничего про соседний проект.

## Чего здесь нет

Поиск — встроенный (`provider: 'local'`), без внешнего сервиса: индекс
собирается вместе со страницами. Аналитики, комментариев и версий
документации нет; понадобятся — это настройки той же темы.
