# Как узнать, что агент ждёт человека, не дожидаясь тишины

План. Убрать 45-секундный таймер из роли основного сигнала — заменить его точным
вопросом от самого CLI, — не откатывая этап-терминал обратно в ACP-сессию.

Написано после прощупывания живых CLI 2026-08-15: Claude Code 2.1.233 и
codex-cli 0.147.0. Всё, что ниже помечено «измерено», получено запуском, а не
чтением документации.

## Задача

Этап маршрута — это вендорский CLI в pty (`stageterminal.go`). Протокола там
нет: когда CLI нужен человек, он рисует коробку на экране и ждёт нажатия. Снаружи
это видно только как «байты перестали приходить», и на этом построен
`AttentionTerminal`: 45 секунд тишины (`terminalQuietFor`) — и карточка говорит,
что ждёт.

Таймер работает, но он груб в обе стороны. Он молчит первые 45 секунд после того,
как человек уже понадобился, и он срабатывает на модели, которая думает дольше
обычного, ничего не рисуя.

ACP-шный `session/request_permission` эту задачу решал бы точно, но он живёт в
другом режиме запуска: адаптер на stdio, без экрана. Один процесс не может быть
обоими — `claude-agent-acp` пишет в stdout JSON-RPC, `claude` рисует туда
интерфейс. Возврат к сессии стоит ровно того, ради чего этап и сделали
терминалом.

## Что нашлось: у обоих CLI есть хуки, и у обоих есть `PermissionRequest`

Хук — это команда, которой CLI отдаёт JSON на stdin и читает решение со stdout.
Это штатная точка расширения, а не внутренняя поверхность.

Claude Code и codex сошлись на совместимом интерфейсе, и это не догадка: имена
полей совпадают вплоть до регистра.

| | Claude Code 2.1.233 | codex-cli 0.147.0 |
| --- | --- | --- |
| поле события | `hook_event_name` | `hook_event_name` |
| событие | `"PermissionRequest"` | `"PermissionRequest"` |
| ответ | `decision: {behavior: "allow"\|"deny", …}` | `decision: {behavior, …}` |
| обёртка ответа | `hookSpecificOutput.hookEventName` | `hookEventName` |

Codex возит с собой JSON Schema `permission-request.command.input` с теми же
именами и теми же зарезервированными полями (`updatedPermissions`), а в его
строках лежат сообщения `PermissionRequest hook denied approval` и
`PreToolUse hook returned permissionDecision:deny …` — то есть он разбирает
клодовский словарь ответов.

Важно, кому это вообще нужно. `cliBin` в таблице видов заполнен только у
`claude` и `codex`; у antigravity, copilot, junie и общего `acp` интерактивного
CLI нет, поэтому `stageRunsInTerminal` для них ложь и они остаются
ACP-сессиями, где вопрос приходит по протоколу. Множество агентов, у которых
есть проблема тишины, — ровно эти два.

## Что измерено на Claude Code

Стенд: `claude --settings <json>` с хуками на `PermissionRequest`, `PreToolUse`
и `Notification`; интерактивный TUI в настоящем pty; задача — записать файл.

**`PermissionRequest` срабатывает и несёт то, что нужно.** Полезная нагрузка:

```json
{"hook_event_name": "PermissionRequest", "tool_name": "Write",
 "tool_input": {"file_path": "…", "content": "…"},
 "permission_suggestions": [{"type":"setMode","mode":"acceptEdits",
                             "destination":"session"}],
 "session_id": "…", "cwd": "…", "transcript_path": "…",
 "permission_mode": "manual"}
```

`tool_input` — это то, что агент собирается сделать, а `permission_suggestions`
— варианты, которые CLI предложил бы сам. Ровно материал для карточки.

**Хук держит, пока человек думает.** Проверено сном на 20 секунд: CLI ждал, и
возвращённое решение было исполнено — файл записан.

```json
{"hookSpecificOutput": {"hookEventName": "PermissionRequest",
                        "decision": {"behavior": "allow"}}}
```

**Коробка в терминале при этом не исчезает.** Пока хук думал, пришёл
`Notification` с `notification_type: "permission_prompt"` — то есть вопрос
показан на экране одновременно с тем, как его задали нам. Это хорошая новость:
не приходится отбирать взаимодействие, отвечает тот, кто раньше.

**Есть и второй сигнал, но он не лучше нашего.** `Notification` с
`notification_type: "idle_prompt"` и сообщением «Claude is waiting for your
input» пришёл через 62 секунды простоя. Это их собственный таймер, и он не
точнее наших 45 секунд — как замена он бесполезен, как дополнение сгодится.

**Режим запуска решает.** В `-p` (неинтерактивном) `PermissionRequest` не
срабатывает вовсе — только `PreToolUse`. И в `auto mode`, который включён по
умолчанию, разрешение не спрашивается: нужен `--permission-mode manual` или
`default`. Для нас это не помеха — этап и так интерактивный, — но проверять
надо в pty, иначе кажется, что хука нет.

**Доставка — аргументом.** `--settings` принимает не только путь, но и
JSON-строку. Хуки вешаются на запуск, в репозиторий пользователя писать ничего
не надо.

## Что измерено на codex: событие есть, доставки нет

Событие в схеме есть (`permission_request` в файле хуков, `PermissionRequest` в
полезной нагрузке), но заставить хук сработать не удалось ни одним из способов:

- `-c hooks=<путь к hooks.json>` — отказ: `hooks` в `config.toml` это структура
  `HooksToml`, а не строка;
- `.codex/hooks.json` в папке проекта — молчание;
- `hooks.json` в `CODEX_HOME` — молчание (сам `CODEX_HOME` работает: codex
  дописал в него `trust_level` проекта);
- `[hooks]` таблицей в `config.toml` с ключами-событиями — молчание;
- всё перечисленное с `--dangerously-bypass-hook-trust`.

Куда ведёт след: у codex есть `hooks.state` в конфиге, персистентное «доверие
хуку» (`failed to write hook trust`, `state_5.sqlite`), настройка
`allow_managed_hooks_only` и пара `hooks.managed_dir` /
`hooks.windows_managed_dir`. Плюс строки `failed to parse plugin hooks config` и
раскладка `hooks/hooks.json` внутри плагина. То есть хуки к codex, похоже,
приезжают **плагином**, а `codex plugin` умеет только `add` из настроенного
маркетплейса — локального пути там нет.

Вывод для плана: на codex первым делом идёт разведка доставки, и она может
кончиться «пока нельзя». Строить надо так, чтобы это ничего не ломало.

## Устройство

Форма уже есть в коде: `acpAdapter` — это колонки на вид (`bin`, `acpArgs`,
`cliBin`, `cliMCPArgs`, `cliResumeArgs`, `cliPromptArgs`, `dropEnv`), и
«добавить агента — это строка, а не ветвление». Прецедент поведения тоже есть:
`stageRunsInTerminal` смотрит, заполнил ли вид `cliMCPArgs`, и вид, который не
заполнил, работает по-старому.

**`cliHookArgs` — ещё одна такая колонка.** Заполнена — точный сигнал; пуста —
45 секунд, как сейчас. Для claude она возвращает `--settings` с JSON-строкой; у
codex остаётся пустой, пока разведка не скажет иначе.

**Хук — это наш же бинарь, перезапущенный.** Прецедент: `maybeRunMCP` в
`main()` и кайтеновский источник, который есть это же приложение под другим
аргументом. Хук читает JSON со stdin, стучится в переднюю дверь, ждёт ответа,
печатает решение. Никакого отдельного артефакта на диске.

**Адрес и право — то же, что у инструментов доски.** У терминала уже есть
grant-токен и `mcpConfig` (`boardToken`, `cliMCPArgs`); хук получает тот же
токен и id терминала аргументами командной строки. Токен живёт ровно столько,
сколько запуск, — та же сделка, что у `internal/boardmcp`.

**Выше передней двери всё уже написано.** `Question`, `QuestionOption`,
`AnswerQuestion`, `Attention` с `options`/`freeText` живы с ACP-времён и не
трогались. Хук ложится на `m.ask(...)` ровно как `client.go` и
`elicitation.go`: блокирует, ждёт, возвращает ответ, снимается по отмене.

**Таймер остаётся полом.** Он единственный сигнал, не зависящий от вендора, и
покрывает то, что хук не покрывает в принципе (ниже). Ничего не удаляется,
меняется только то, кто говорит первым.

## Что решить до кода

**Экран с вариантами придётся вернуть.** Его убрали сознательно
(`docs/deferred.md`, «На вопрос по протоколу теперь некому ответить»), и весь
смысл этапа-терминала в том, что ничего нашего поверх того экрана не рисуется.

Но здесь правило не нарушается, а размечается заново, и измерение это
поддерживает: коробка в терминале остаётся на месте, вопрос просто задан **и**
нам тоже. То есть мы не рисуем поверх чужого экрана и не отбираем ответ — мы
показываем тот же вопрос там, где человек смотрит на карточку, и отвечает тот,
кто раньше.

Предлагаемое правило: **спрашиваем у себя только то, что пришло хуком.**
Всё остальное по-прежнему живёт в терминале и по-прежнему видно как тишина.
Это формулируется одной фразой и не требует от человека знать, какой у него
агент.

## Чего это не закроет

Всё, что случается **вне цикла агента**, — там модель ещё не в игре и хука нет:

- вопрос о доверии к папке (измерено: `claude` в свежей папке останавливается на
  «Is this a project you trust?» до единого хука);
- логин;
- выбор «продолжить разговор?» при отказавшемся resume.

Это остаётся тишиной, и это ровно то, ради чего `terminalQuietFor` не выкидывается.

## Порядок работ

1. **Разведка доставки у codex.** Одна задача, потолок — день. Ответ либо
   «вот как», либо «пока никак, ждём локальных плагинов». До ответа на codex
   ничего не строится, и это ничего не блокирует.
2. **Колонка `cliHookArgs`** в `acpAdapter` + сборка `--settings` для claude,
   рядом с `cliMCPArgs` в `terminal_command.go`. Пустая колонка = сегодняшнее
   поведение, с тестом на это.
3. **Режим хука в `main()`**: чтение JSON со stdin, POST в переднюю дверь,
   печать решения. Первой строкой после `updater.HandleHelperMode()` и
   `maybeRunMCP` — по той же причине, по которой они там.
4. **Маршрут на передней двери**: грант проверяется как у `boardmcp`, вопрос
   уезжает в `m.ask(...)`, ответ возвращается решением. Отказ по отмене и по
   выключению приложения — как в `question.go`.
5. **Экран.** Варианты на карточке и в уведомлении, из
   `permission_suggestions` плюс «разрешить» / «запретить». Уведомление уже
   умеет не повторяться (`internal/acp/attentionack.go`).
6. **`Notification`** с `notification_type: "permission_prompt"` — вторым
   сигналом на случай, если хук не ответил. `idle_prompt` не берём: он не
   точнее нашего таймера.
7. **`docs/guide/`** — что теперь спрашивают на карточке, а что по-прежнему в
   терминале; и `docs/deferred.md`, где запись «некому ответить» становится
   неверной для двух видов из шести.

## Что осталось непроверенным

- **Потолок ожидания хука.** 20 секунд измерены, дальше не проверялось. У
  Claude Code в конфиге хука есть поле `timeout`; надо узнать его максимум и
  что происходит по истечении — если откат на вопрос в терминале, это идеальная
  деградация и ради неё стоит специально измерить.
- **Элицитации.** В списке событий Claude Code есть `Elicitation` и
  `ElicitationResult`; если через них видны формы `AskUserQuestion`, карточка
  сможет показывать не только разрешения, но и вопросы с вариантами.
- **`PermissionDenied`** — есть у обоих, не смотрели.
